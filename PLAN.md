# Разработка приложения «Библиотека аудиокниг»

Ты выступаешь в роли Senior Frontend-разработчика и UI/UX-дизайнера. Необходимо разработать полноценное персональное приложение для хранения и прослушивания аудиокниг.

Это личная библиотека аудиокниг, в которой пользователь самостоятельно загружает аудиофайлы, организует их в коллекции, слушает, отслеживает прогресс и статистику прослушивания.

Приложение должно быть ориентировано преимущественно на мобильные устройства, поддерживать установку в качестве PWA и работать офлайн.

Важно: требуется полноценное работающее приложение, а не демонстрационный макет с неработающими кнопками.

## Принятые решения

Эти правила уточняют разделы ниже и имеют приоритет при реализации.

- Один аудиофайл — одна книга. Загрузка нескольких файлов создаёт несколько книг. Глав, склейки файлов и очереди воспроизведения нет.
- Книга считается прослушанной, когда позиция достигла 95% длительности или дорожка доиграла до конца. Позиция больше нуля и ниже этого порога — «в процессе». Нулевая позиция — «не начата».
- При переходе между разделами воспроизведение продолжается, внизу остаётся мини-плеер. Закрытие вкладки сохраняет позицию.
- Статистика считает реальное время, пока аудио играет. Пауза не учитывается. Скорость воспроизведения не умножает часы.
- Книгу можно удалить с подтверждением. Удаляются файл, обложка, прогресс и вхождения в коллекции. Накопленная статистика прослушивания сохраняется.
- Метаданные читаются библиотекой. Если их нет, название берётся из имени файла. Все поля можно править позже.
- Интерфейс на русском.
- Скорость воспроизведения одна на всё приложение и сохраняется между сессиями.
- Неделя начинается с понедельника. Даты показываются в локальном времени устройства.
- Сброс статистики очищает часы и историю и не меняет позиции книг.
- Жанр и описание видны в форме редактирования и на экране плеера.

## 1. Технологический стек

Используй строго следующий основной стек:

- Vue 3.
- TypeScript.
- Vite.
- Composition API (`<script setup>`).
- HTML5 Audio API для воспроизведения аудиокниг.
- IndexedDB для локального хранения аудиофайлов и пользовательских данных.
- PWA через `vite-plugin-pwa`.
- CSS или SCSS для стилизации.

Не используй React, Nuxt, Next.js и другие альтернативные фреймворки.

Не добавляй избыточные библиотеки. Дополнительные зависимости используй только в случае реальной необходимости.

Приложение будет размещено на GitHub Pages. Серверная часть, регистрация, авторизация и платные сторонние сервисы не нужны.

Все пользовательские данные должны храниться локально на устройстве.

## 2. Основные разделы приложения

Предусмотри следующую структуру:

1. **Библиотека** — главная страница со всеми аудиокнигами.
2. **Коллекции** — пользовательские подборки книг.
3. **Статистика** — история и показатели прослушивания.

Блок «Продолжить прослушивание» должен находиться непосредственно на главной странице библиотеки.

На мобильных устройствах используй удобную нижнюю навигацию между основными разделами.

## 3. Главная страница — библиотека

Главная страница должна содержать:

**Шапка:**

- Название приложения и минималистичный логотип.
- Кнопка добавления аудиокниг.

**Продолжить прослушивание:**

Это один из главных элементов интерфейса.

Отображай последнюю прослушиваемую книгу:

- Обложка.
- Название.
- Автор.
- Текущий прогресс.
- Процент завершения.
- Кнопка продолжения воспроизведения.

При нажатии на карточку пользователь должен попадать непосредственно в плеер с сохранённой позиции.

Если пользователь ещё не начинал слушать книги, этот блок можно скрывать или показывать ненавязчивое предложение добавить первую книгу.

**Библиотека:**

Отображай все загруженные книги.

Карточка книги должна включать:

- Обложку.
- Название.
- Автора.
- Продолжительность.
- Прогресс прослушивания.
- Процент завершения.

Добавь поиск по названию и автору.

Реализуй фильтрацию:

- Все книги.
- Не начатые — позиция равна нулю.
- В процессе — позиция больше нуля и меньше 95% длительности.
- Прослушанные — позиция достигла 95% длительности или дорожка доиграла до конца.

Добавь сортировку:

- По названию.
- По автору.
- По дате добавления.
- По последнему прослушиванию.

Предусмотри переключение между компактным списком и сеткой обложек.

## 4. Добавление аудиокниг

Реализуй загрузку одного или нескольких аудиофайлов с устройства. Один файл становится одной книгой. Несколько файлов за раз создают несколько книг. Глав, склейки в одну дорожку и очереди воспроизведения нет.

Поддерживаемые форматы:

- MP3.
- M4A.
- AAC.
- OGG.
- WAV.
- M4B.

Учитывай реальную поддержку браузером конкретных аудиокодеков.

При добавлении книги пользователь может указать:

- Название.
- Автора.
- Исполнителя / чтеца.
- Обложку.
- Жанр.
- Описание.

Читай метаданные библиотекой: так быстрее и надёжнее, чем разбирать теги вручную. Автоматически используй имя файла как первоначальное название книги, если метаданные недоступны.

Все метаданные должны быть доступны для последующего редактирования. Жанр и описание видны в форме редактирования и на экране плеера.

Книгу можно удалить с подтверждением. Вместе с ней удаляются аудиофайл, обложка, позиция воспроизведения и вхождения в коллекции. Уже накопленные часы и история статистики сохраняются.

Сохраняй аудиофайлы в IndexedDB. Учитывай большие размеры файлов и не загружай их целиком в оперативную память без необходимости.

Добавь обработку ошибок, проверку доступного места и отображение состояния импорта.

## 5. Аудиоплеер

Создай отдельный удобный экран прослушивания.

Основные элементы:

- Обложка книги.
- Название и автор.
- Исполнитель.
- Полоса прогресса.
- Текущая позиция.
- Общая продолжительность.
- Кнопка Play / Pause.
- Перемотка назад на 15 секунд.
- Перемотка вперёд на 30 секунд.
- Регулировка скорости воспроизведения.

Предусмотри следующие скорости:

0.5x, 0.75x, 1x, 1.25x, 1.5x, 1.75x, 2x и 2.5x.

Дополнительно:

- Перемещение по аудиодорожке с помощью ползунка.
- Автоматическое сохранение позиции.
- Восстановление позиции после перезапуска приложения.
- Кнопка возврата в библиотеку.

Реализуй сохранение прогресса периодически во время воспроизведения, при паузе, при уходе со страницы и при закрытии вкладки.

При переходе в библиотеку, коллекции или статистику воспроизведение не останавливается. Внизу экрана остаётся мини-плеер с обложкой, названием, кнопкой Play / Pause и переходом на полный экран плеера. Скорость одна на всё приложение и сохраняется между сессиями.

Используй Media Session API для поддержки системных элементов управления воспроизведением на совместимых устройствах.

Учитывай ограничения мобильных браузеров относительно фонового воспроизведения.

## 6. Статистика прослушивания

Реализуй отдельную страницу статистики.

Она должна давать пользователю представление о его активности и привычках прослушивания аудиокниг.

Основные показатели:

**Общая статистика:**

- Общее время прослушивания.
- Количество добавленных книг.
- Количество завершённых книг.
- Количество книг в процессе.
- Количество ещё не начатых книг.

**Статистика по периодам:**

- Время прослушивания за текущую неделю.
- Время прослушивания за текущий месяц.
- Количество прослушанных часов по дням.
- Динамика активности.

**История:**

- Последние прослушиваемые книги.
- Когда пользователь слушал конкретную книгу.
- Последняя позиция воспроизведения.

Используй понятные графики и аккуратные визуальные карточки.

Не перегружай страницу большим количеством диаграмм. Основные показатели должны считываться быстро.

Важные технические требования:

- Учитывай только фактическое время воспроизведения, а не время, проведённое на странице плеера.
- Считай реальное время, пока аудио играет. Скорость 2x не удваивает часы в статистике.
- Не увеличивай статистику во время паузы.
- Исключай двойной учёт времени при переключении страниц. Мини-плеер и полный экран — один сеанс.
- Сохраняй историю прослушивания в IndexedDB.
- Используй локальное время устройства для отображения дат.
- Неделя начинается с понедельника.
- Завершённой считай книгу, у которой позиция достигла 95% длительности или дорожка доиграла до конца.

Предусмотри возможность сброса статистики с подтверждением действия. Сброс очищает часы и историю и не меняет позиции книг.

## 7. Продолжить прослушивание

Реализуй механизм автоматического отслеживания последней прослушиваемой книги.

На главной странице всегда должна отображаться книга, которую пользователь слушал последней.

Сохраняй:

- Идентификатор книги.
- Последнюю позицию воспроизведения.
- Общую продолжительность.
- Дату последнего прослушивания.
- Текущий прогресс.

При повторном открытии приложения пользователь должен иметь возможность одним нажатием продолжить прослушивание.

Если пользователь переключается между несколькими книгами, не теряй прогресс предыдущих книг.

Для каждой книги сохраняй собственную позицию воспроизведения.

## 8. Коллекции

Реализуй отдельный раздел для создания пользовательских коллекций аудиокниг.

Коллекции нужны для удобной организации библиотеки.

Примеры:

- Фантастика.
- Детективы.
- Саморазвитие.
- Классическая литература.
- Книги перед сном.
- В планах к прослушиванию.

Пользователь должен иметь возможность:

1. Создавать собственные коллекции.
2. Задавать название.
3. Добавлять описание.
4. Выбирать обложку коллекции или использовать автоматически сформированную из обложек книг.
5. Добавлять в коллекцию несколько книг.
6. Удалять книги из коллекции без удаления из основной библиотеки.
7. Переименовывать и редактировать коллекции.
8. Удалять коллекции с подтверждением действия.

Одна книга может одновременно входить в несколько коллекций.

При открытии коллекции отображай:

- Название.
- Описание.
- Количество книг.
- Список входящих книг.
- Общий прогресс прослушивания книг в коллекции.

Добавь возможность запускать воспроизведение книги непосредственно из коллекции.

Коллекции должны храниться в IndexedDB и сохраняться после перезапуска приложения.

## 9. Хранение данных и офлайн-режим

Используй IndexedDB для хранения:

- Аудиофайлов.
- Метаданных книг.
- Обложек.
- Прогресса воспроизведения.
- Коллекций.
- Статистики.
- Истории прослушивания.
- Пользовательских настроек.

Не используй localStorage для хранения аудиофайлов.

Настрой полноценную PWA:

- Установка на главный экран смартфона.
- Web App Manifest.
- Service Worker.
- Кэширование необходимых ресурсов приложения.
- Работа интерфейса без интернета.
- Сохранение загруженных аудиокниг в IndexedDB.

Реализуй проверку доступного хранилища через Storage API.

По возможности запрашивай постоянное хранилище через `navigator.storage.persist()`.

Пользователь должен понимать, что его аудиокниги и данные хранятся локально, не синхронизируются между устройствами и могут быть потеряны при очистке данных браузера.

Основной приоритет — мобильные телефоны.

Визуальные ориентиры:

## 11. Архитектура проекта

Раздели приложение на логические модули:

- `components` — переиспользуемые компоненты.
- `views` — страницы приложения.
- `composables` — переиспользуемая логика Vue.
- `services` — работа с IndexedDB, аудио и хранилищем.
- `stores` — состояние приложения, если используется Pinia.
- `types` — TypeScript-типы.
- `assets` — изображения, иконки и стили.

Вынеси управление аудиоплеером в отдельный модуль.

Работу с IndexedDB также реализуй через отдельный сервис.

Не помещай всю бизнес-логику в один компонент.

Учитывай:

- Типизацию TypeScript.
- Обработку ошибок.
- Освобождение Object URL.
- Отсутствие утечек памяти.
- Сохранение состояния приложения.
- Миграции структуры IndexedDB.
- Корректную работу с большими аудиофайлами.

- Хранить их локально.

Главный приоритет — надёжность, удобство и качественный пользовательский опыт.
